# Draft packs

First-party packs by Made with Best Practice start here before they're
published. There are no drafts right now: all 21 first-party packs are in
`packs/`. This page keeps what each one still needs checked on real hardware.
`tools/build_index.py` reads only `packs/`, so nothing in `drafts/` is in
`index.json` or reaches the app.

## From draft to published

A draft moves to `packs/` only when all of these are done:

1. **Tested on real hardware.** Every button is pressed on a real device or
   service, and the model and firmware are noted.
2. **Pull request with the checklist.** Open a PR that fills in the
   [pull request checklist](../.github/pull_request_template.md), including
   the doc links below and the hardware tested. Fix or remove any button that
   didn't work; don't publish a button nobody has pressed.
3. **Move and rebuild.** `git mv drafts/<id>.json packs/<id>.json`, set
   `version` to `1.0.0`, run `python tools/build_index.py`, and commit the
   pack and the updated `index.json` together. Remove its row here.

## Published scene packs

Movie night, Game night, Bedtime and Projector night were published on
2026-10-12 after testing against the Home Assistant demo server (Home
Assistant 2026.2, `demo:` devices), not real hardware: every service call
and every macro's Home Assistant steps returned success and changed the
demo entity's state, each macro ran again with its optional devices empty
(only the steps without them ran), and the TV key steps were checked
against [`schema/keys.json`](../schema/keys.json). Still to check on real
devices: that `close_cover` lowers a motorized projector screen (some
report down as open), Projector on (IR) with a real IR hub and projector
(the demo has no `remote` entity, so only the call's shape was checked) and
that it doesn't turn an already-on projector off, TV key steps on a real
TV, and Bedtime's night temperature on a °F setup.

Intermission and Late night were published on 2026-10-13 the same way, with
demo switches and `select.speed` standing in for the receiver's night mode,
dialogue and dynamic range settings. Still to check on real devices: a
receiver that exposes these in Home Assistant (option names must match
exactly; a wrong one fails), a light group, and the TV keys on a real TV.

## Published after protocol checks

IR devices via Home Assistant and Sonos were published on 2026-10-13 without
hardware. IR: every button's call went through Home Assistant 2026.2's own
`remote.send_command` service to a recording `remote` entity (the demo has
none), with and without a device name, and the data passed Broadlink's send
schema. Still to check: a real Broadlink (with no device name, Broadlink only
accepts `b64:` codes) and a Harmony. Sonos: every request was checked
against the local UPnP control on port 1400 (control URLs, quoted
`SOAPACTION`, SOAP envelopes and arguments) as SoCo sends it. Still to check:
an Arc, a Beam or Ray and an Arc Ultra, Switch to TV on an HDMI eARC bar, and
a grouped bar (AVTransport must go to the group coordinator).
